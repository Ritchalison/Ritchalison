## How I Approach Technical Work

One thing that increasingly defines how I learn is that I don't particularly like stopping at:

> "Run this command."

I want to understand:

- What is happening?
- Why are we doing it?
- What changed?
- Why did it fail?
- How do we know it worked?
- What evidence supports the conclusion?
- What security implication does it have?

That approach is becoming increasingly important as I move deeper into cybersecurity.
